# GitHub media ecosystem for CutSteward

CutSteward product scope: macOS and Windows only. Linux references below
describe upstream projects for research completeness, not supported hosts.

Research snapshot: **2026-08-08**. This is a conservative executable-selection memo, not an installation plan. Only official project repositories, tagged releases, registries, manuals, and vendor security/license pages were used. “Current” below means the newest stable tag or official source release visible on the research date; when a project has no release, the exact inspected commit is given.

## Executive decision

Keep the default workstation small:

1. **Baseline: FFmpeg + ffprobe only.** They cover decode/encode, filters, stream copy, thumbnails, audio transforms, subtitle burn-in, packaging, and machine-readable probing. Every extra runtime below adds a narrower capability, a larger attack surface, or both.
2. **Recommended opt-ins, in adoption order:** whisper.cpp, OpenTimelineIO, MediaInfo, PySceneDetect, VMAF, Remotion, then capcut-cli for an explicitly selected CapCut workflow.
3. **Do not silently install any opt-in.** Pin release artifacts and model files, record hashes, prohibit implicit model/network downloads during jobs, and run hostile media in a resource- and network-constrained worker.
4. **CapCut stays a manual final-render handoff.** `capcut-cli` is useful but unofficial and edits an undocumented local schema. It is not evidence of an official CapCut automation API or a reliable cross-version round trip.
5. **Acquisition is rights-gated.** yt-dlp belongs behind an explicit “owned/licensed/authorized source” decision; never use it to bypass DRM, access controls, authentication, or site rules.

### Why the shortlist is this small

- FFmpeg already handles most media transforms. A second general pipeline earns installation only when it adds a distinct contract: offline ASR, neutral timelines, normalized metadata, scene analysis, reference QC, code-native composition, or an explicitly requested CapCut bridge.
- OpenTimelineIO is the preferred **timeline interchange** layer; Remotion is a **code-native renderer**; neither pretends to be the other.
- whisper.cpp is the portable transcription default. faster-whisper remains useful for high-throughput NVIDIA workloads, but its Python/CTranslate2/CUDA/model dependency graph is much heavier.
- MediaInfo complements ffprobe; it does not replace it. VMAF complements deterministic encode tests; it does not replace visual review.

## CapCut interoperability: guarded manual handoff

### What is and is not supported

The official CapCut material found describes an interactive signed desktop app for [Windows and macOS](https://www.capcut.com/resource/capcut-desktop-download) and a GUI [export workflow](https://www.capcut.com/help/export-videos-in-capcut). Official help also describes project import limitations and flattened exported media, not an editing CLI or a stable public draft schema ([project import](https://www.capcut.com/help/import-a-previous-project-into-the-current-project)). Therefore:

- `capcut-cli` is an **independent community interoperability tool**, not a vendor API.
- CutSteward admits this bridge only on its supported macOS/Windows hosts, and final render remains a CapCut Desktop handoff.
- The installed CapCut version must be detected and recorded at runtime. Do not claim compatibility from a generic “latest” download page.

The project’s own [version matrix](https://github.com/renezander030/capcut-cli/blob/v0.17.2/docs/version-support.md) is appropriately cautious: CapCut 6.2.8 is fixture-tested; 6.5–8.0 and 9.x are expected-compatible but unverified; 8.7 Windows has only reported/synthetic evidence with real validation pending; 10.x is reported corrupted and write-guarded. JianYing 6+ encrypted-draft files are detected but not decrypted. These facts rule out unattended writes across arbitrary app versions.

### Required workflow

1. Keep CapCut/JianYing closed. Copy the entire draft directory and operate on the copy; preserve the tool’s `.bak` and the original store.
2. Pin npm `capcut-cli@0.17.2` by version **and integrity** above. Do not accept `latest` during an automated run.
3. Run read-only `capcut version` and `capcut diagnose` first. Stop on unknown/newer schema, app-version drift, encrypted JianYing, divergence, corruption, or an active editor process. Never normalize a refusal with `--force-write` in unattended work.
4. Use `--dry-run`, then `lint`; write one copied draft; reopen and visually inspect it before any batch operation.
5. Have a human open the copied draft in the exact tested desktop build, review timing/effects/fonts/media relinks, and invoke final export. A proxy made by `capcut render` is not CapCut’s final renderer.
6. Do not feed an untrusted draft, spec, folder name, caption style, remote media URL, or JSONL job to the process. Keep secrets out of job payloads and logs.

The [0.17.1 changelog](https://github.com/renezander030/capcut-cli/blob/v0.17.2/CHANGELOG.md) documents why the version floor matters: `export --batch` command injection through a hostile draft-folder name, FFmpeg filter injection through caption colour, a `compile` path escape, predictable temporary files, credential echo from `serve`, and related path handling were fixed there. v0.17.2 is a documentation-only follow-up carrying those fixes.

## Execution policy for every selected tool

1. **Pin identity:** version/tag, download URL, checksum/signature, license, target OS/architecture, and optional feature/build flags. Never resolve `latest` inside a production job.
2. **Separate install from run:** setup may fetch approved artifacts; rendering/transcription jobs run offline unless a source URL or model fetch was explicitly authorized.
3. **Treat inputs as hostile:** subprocess isolation; no shell interpolation; explicit argument arrays; restricted protocols/delegates/plugins; file-count, byte, pixel, frame, duration, CPU, RAM, disk, and wall-clock ceilings; output confined to a job directory.
4. **Treat job formats as active:** Remotion projects and Blender files can execute code; MLT XML and GPAC graphs can access devices/network; OTIO adapters and yt-dlp plugins import Python; CapCut drafts can reach shell/filter/path bugs. “JSON” does not imply inert.
5. **Control models:** pin weight provenance, hash, license, architecture, expected size, and memory/VRAM. Never run arbitrary pickle/checkpoint formats from a user upload.
6. **Verify media deterministically:** ffprobe/MediaInfo contract checks, decode smoke test, duration/frame/audio-stream checks, render exit status, output hash/size, and selected visual/audio QA. VMAF needs a controlled reference; no metric replaces human approval for creative output.
7. **Preserve evidence:** structured stdout/stderr, exact command and tool versions, input/output manifests, and a redacted failure bundle. Never log credentials, cookies, provider tokens, draft personal paths, or subtitle content unless the job policy requires it.

## Final recommended package shape

- **`setup` / lean UI:** no media-tool mutation.
- **`setup:full` baseline:** pinned FFmpeg/ffprobe only.
- **Small opt-in packs:** `transcription-local` (whisper.cpp + pinned model), `timeline-interchange` (OTIO + pinned adapters), `metadata-qc` (MediaInfo), `scene-analysis` (PySceneDetect), `reference-qc` (VMAF or an FFmpeg build that records libvmaf), `motion-code` (Remotion after license review), and `capcut-draft-bridge` (capcut-cli 0.17.2 with guarded manual export).
- **Large/specialist packs:** Blender, MLT, GPAC, ImageMagick, audio-separator, faster-whisper/CUDA, auto-editor.
- **Rights-gated acquisition pack:** yt-dlp with no ambient plugins/config/cookies and an explicit lawful-source assertion.
- **Manual applications:** CapCut Desktop and LosslessCut.
- **Rejected:** pyCapCut and the cutcli remote-installer path; defer libopenshot unless OpenShot interoperability becomes a concrete requirement.

This shape gives the agent a dependable universal media core while keeping vendor draft mutation, executable projects, model ecosystems, GPU stacks, and acquisition tools outside the trusted baseline.
